# 데이터 연결과 확장

문서 폴더나 REST API가 기본 수집 형식에 맞으면 설정만 바꿔 연결합니다.
다른 인증 방식이나 응답 형식을 쓰는 시스템은 소스 어댑터를 작성해 연결합니다.
회사별 SDK와 인증 처리는 이 어댑터에 두며, 코어에 추가하지 않습니다.

## 문서 폴더 연결

폴더 수집기는 UTF-8로 작성한 `.md`, `.txt` 파일을 읽습니다. 숨김 경로와 심볼릭 링크는 건너뜁니다.
문서 경로를 바꿀 때는 설정의 경로와 컨테이너의 읽기 전용 마운트도 함께 맞춥니다.

기본 수집 한도는 문서 1,000개, 파일당 2 MB, 전체 20 MB입니다. 한도를 넘으면 일부만 가져온 목록을
정상 결과로 넘기지 않고 수집에 실패합니다. 큰 디렉터리는 연결할 자료의 용도에 따라 여러 소스로 나눕니다.

## REST API 연결

`examples/rest-source.toml`에서 주소, 필드 매핑, 인증에 사용할 환경변수 이름을 지정합니다.
기본 수집기는 정해진 HTTPS 주소에 GET 요청을 보내고 다음 형식의 응답을 받습니다.

```json
{
  "items": [{"id": "policy-1", "text": "Policy text", "title": "Policy"}],
  "next_cursor": null
}
```

다음 페이지가 있으면 응답의 `next_cursor`에 문자열을 넣습니다. 수집기는 같은 주소에 `cursor` 쿼리를 붙여
다시 요청합니다. 응답에 담긴 다른 URL로 이동하거나 HTTP 리다이렉트를 따라가지는 않습니다.

기본 한도는 100페이지, 문서 1,000개, 응답당 4 MB, 전체 20 MB입니다.
잘못된 설정이나 예상하지 못한 응답 때문에 수집량이 계속 늘어나는 것을 막기 위한 제한입니다.
문서 필드 값은 문자열이어야 하고 `id`는 비어 있으면 안 됩니다.
이 응답 형식이나 Bearer 인증을 제공하지 않는 API는 아래 방법으로 별도 어댑터를 작성합니다.

## 새 수집기 작성

소스마다 고유한 `id`와 `scan(checkpoint)` 메서드가 필요합니다.
수집 결과는 `Snapshot(documents, checkpoint, complete)`로 반환합니다.

| 값 | 작성 기준 |
|---|---|
| `Document.id` | 원본의 안정된 식별자입니다. 제목이나 조회 순서로 만들지 않습니다. |
| `Document.source_id` | 소스의 `id`와 같아야 합니다. 소스 ID를 바꾸면 새 소스로 취급합니다. |
| `text` | 검색할 본문을 넣습니다. 제목·출처 URL·리비전·원본 갱신 시각은 나머지 필드에 담습니다. |
| `updated_at` | 원본의 수정 시각입니다. 알 수 없으면 비워 두고, 자료를 읽은 시각으로 대신하지 않습니다. |
| `complete` | 이 소스의 전체 목록을 빠짐없이 수집했는지 표시합니다. |

### 전체 목록과 실패 구분

`complete=True`는 **그 소스에 속한 모든 문서를 반환했다**는 뜻입니다. 변경된 문서만 주는 증분 API를
그대로 연결하면 나머지 문서가 삭제된 것으로 처리될 수 있습니다. 어댑터에서 전체 목록을 복원하거나,
변경분만 받아도 기존 문서를 삭제하지 않도록 증분 반영 절차를 별도로 구현해야 합니다.

권한 오류, 페이지 누락, 타임아웃이 발생했다면 예외를 발생시키거나 `complete=False`로 반환합니다.
실패를 빈 문서 목록으로 바꾸면 안 됩니다. 수집이 완전하다고 표시한 빈 목록은 기존 문서를 삭제할 수 있습니다.

기본 수집기도 매번 전체 목록을 읽습니다. 체크포인트가 있다고 수집을 생략하지는 않으며,
내용이 바뀌지 않은 문서는 버전을 비교한 뒤 임베딩을 생략합니다.

### 어댑터 예제

아래 예제의 `client`는 모든 페이지를 읽고 인증을 처리하는 클라이언트입니다.
`read_all_pages()`는 구현해야 할 동작을 보여주기 위한 이름입니다.

```python
from taco_shell_rag.core.contracts import Document, Snapshot


class PolicySource:
    id = "policies"

    def __init__(self, client):
        self.client = client

    def scan(self, checkpoint):
        rows, cursor = self.client.read_all_pages()
        documents = [
            Document(
                id=row["id"],
                source_id=self.id,
                text=row["text"],
                title=row.get("title", ""),
                url=row.get("url", ""),
                updated_at=row.get("updated_at", ""),
            )
            for row in rows
        ]
        return Snapshot(documents, checkpoint=cursor, complete=True)
```

일부 페이지만 읽었거나 읽기 권한을 잃었다면 `read_all_pages()`가 정상 목록을 반환하지 않도록 만듭니다.
가짜 API 응답으로 이런 실패 상황도 검사합니다.

### 설정에 등록

어댑터를 작성한 뒤에는 `config.py`의 `SourceConfig`와 소스를 생성하는 함수에 등록합니다.
예제 코드를 추가하는 것만으로 새 `type`을 사용할 수 있게 되지는 않습니다.
자동으로 플러그인을 탐색하거나 외부 코드를 다운로드하는 기능도 없습니다.

원본 API와 인증 정보는 Python 수집기가 사용합니다. Go 검색 서버에는 설정의 소스 ID만 필요하므로
수집기별 옵션을 추가할 필요는 없습니다. 설정에는 토큰 값 대신 환경변수 이름을 적고,
컨테이너가 원본 데이터와 네트워크에 접근할 수 있는지도 확인합니다.

문서를 검색에 반영하는 코드와 검색 코드는 새 수집기를 추가할 때 그대로 사용할 수 있습니다.
체크포인트 저장은 코어가 문서를 검색에 반영하고 이전 데이터를 정리한 뒤 처리하므로 어댑터에서 먼저 갱신하지 않습니다.
벡터 저장에 실패한 문서는 새 버전을 검색에 반영하지 않습니다. 이전 버전의 정리 작업은 재시도할 수 있도록 문서 DB에 기록합니다.

## 수정할 코드 위치

아래 경로는 `src/taco_shell_rag/` 기준입니다.

| 위치 | 용도 |
|---|---|
| `core/contracts.py` | 문서·스냅샷·청크 자료형과 소스·추론·저장소 인터페이스 |
| `indexer/sources.py` | 폴더·REST 수집기와 입력 한도 |
| `indexer/pipeline.py` | 수집한 문서의 검색 반영 순서와 체크포인트 저장 |
| `indexer/catalog.py`, `indexer/vectorstore.py` | 문서 버전·BM25 관리와 벡터 저장 |
| `adapters/inference.py` | 임베딩·리랭커 HTTP API 연결 |
| `config.py` | 설정 검사와 사용할 어댑터 선택 |
| `agent/` | 선택적 답변 생성 |

검색 구현은 Go의 `internal/retriever/`에 있습니다. 추론 API나 벡터 저장소를 바꾼다면 공통 인터페이스를
구현하는 어댑터를 연결하고, Python이 저장하는 형식과 Go가 읽는 형식을 함께 확인합니다.

## 연결 후 확인

테스트에서는 외부 계정 대신 가짜 응답을 사용합니다. 정상 목록 외에도 중복 ID, 문서가 하나도 없는 전체 목록,
페이지 누락, 저장 도중 실패와 재시도를 확인합니다. 기존 예제는 `tests/test_sources.py`,
`tests/test_publication_failures.py`에 있습니다.

임베딩 모델이나 벡터 공간을 바꾸었다면 새 컬렉션과 SQLite 파일을 만들고 다시 색인합니다.
자료별 접근 제어가 필요하다면 권한이 다른 자료를 같은 인스턴스에 연결하지 않습니다.
